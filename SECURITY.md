# Security

Rampart is a self-hosted CMMC Level 2 readiness tool. It holds an assessment's evidence, its
POA&M and its audit trail, so it is a Security Protection Asset: it should itself meet the NIST SP
800-171 requirements it touches. This file says how to report a flaw, what we think can go wrong,
which of those requirements Rampart meets on its own, and what it doesn't do yet.

## Supported versions

Rampart has no tagged releases yet. Only the latest commit on the `main` branch gets security
fixes. If you run an older checkout, update to the newest `main` before you report, and say which
commit you ran.

## Reporting a vulnerability

Report it privately through GitHub private vulnerability reporting: open this repository's
**Security** tab and choose **Report a vulnerability**. Never open a public issue, pull request or
discussion for a security problem, since that shows it to everyone before a fix exists.

Please include:

- what an attacker can do, and which part it is in (api, web app, file uploads, audit log, secret
  key, CI or the install)
- the steps to reproduce it, on a scratch database (never one holding real assessment data)
- the commit you ran, your OS and Node version, and whether `HOSTED` or `FIPS_MODE` was set
- any logs or requests that show it, with passwords, codes, cookies and keys removed

What you can expect from us:

- **Acknowledgement within 5 business days.**
- **A fix or a written plan within 30 days** for a high or critical issue (CVSS 7.0 or higher).
  Lower-severity issues are fixed in the normal flow of work.
- A GitHub Security Advisory once a fix is on `main`, crediting you unless you ask us not to.
- There is no bug bounty.

Please give us a reasonable chance to fix a problem before you talk about it publicly. We won't
take action against good-faith research that stays on your own install and never touches someone
else's data.

two-step secrets, and **CI**. Each cell gives the threat, the mitigation and the code that holds
it.

## Known gaps

These are known and accepted for now. Each is either parked as a later plan or a host's job.

- **FIPS is documented, not proven.** Standard Node builds on Windows have no FIPS provider, so
  `FIPS_MODE` defaults to `off`. With `FIPS_MODE=required`, PBKDF2-SHA-256 is used for new
  passwords, but nothing has run it on a real FIPS-enabled Node, and there is no rehash at sign-in:
  argon2 hashes stored before FIPS was required keep working until that user changes the password.
- **The audit chain is unkeyed and unanchored.** Each hash is plain SHA-256 with no secret, and
  nothing outside the database records the chain. Verify catches an event edited in place, an event
  deleted from the middle, and a row with no hash. It can't catch anyone who can write the
  database file directly and either appends a forged event with a correctly computed hash, or
  rewrites every event from an edit to the newest with new hashes, or removes the newest events.
  Noting the "Newest hash" doesn't help, because ordinary new events change it too. Only an
  anchor outside the database closes this; a signed audit export is parked. Until then, protect
  the database file itself (host access control and backups).
- **No virus scanning.** Uploads are checked by type, structure and size only. Scanning with an
  antivirus engine is parked.
- **No encryption at rest.** The SQLite database and the file store are plain files. Use the
  host's disk encryption (BitLocker, FileVault or LUKS). Built-in encryption at rest is parked.
- **Windows key-file ACLs.** On Windows, mode 0o600 has no effect, so the generated
  `apps/api/data/rampart-secret.key` inherits the data folder's ACLs and other local accounts may
  read it. Restrict it with `icacls`, or keep the key in `RAMPART_SECRET_KEY` from a secret store,
  before hosting (an open item in the handoff queue).
- **Synchronous upload parsing.** The content and zip checks run on the request thread. They are
  bounded and linear in time, but a burst of 25 MiB uploads still holds the event loop while each
  is checked.
- **TOTP only.** WebAuthn and passkeys are parked.

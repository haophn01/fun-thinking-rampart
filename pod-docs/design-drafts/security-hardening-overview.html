Security hardening: Rampart as a Security Protection Asset

Rampart meets the NIST SP 800-171 requirements it touches: MFA for every user, session controls and lock, password policy, sign-in notice and a tamper-evident audit log. It also closes the web-app gaps: access-control tests on every route, supply-chain CI, CSP on the served pages, rate limits and upload hardening. Local use is unchanged except for MFA, and a HOSTED=true mode is ready for deployment.

Parts

PartDoes
auth controlsSessions 30 min / 8 h, rotation, sign out everywhere; blocklist; no reuse of the last 5; temporary password; sign-in notice; 15-min lock screen
mfaTOTP for every user, 10 recovery codes, replay guard, encrypted secrets, admin reset
http hardeningProduction web served by the API with a strict CSP and headers; HOSTED mode (__Host- Secure cookie, HSTS, trustProxy); rate limits
uploadsByte-based allowlist (PDF, PNG, JPEG, DOCX, XLSX, TXT/CSV), zip-bomb guard, filename sanitizing
audit chainHash-chained audit log with Verify in Settings (migration 0006)
CI supply chainSHA-pinned actions, OSV/pnpm audit, Semgrep, pnpm allowBuilds / minimumReleaseAge / trustPolicy
testsEvery-route authz/CSRF/IDOR matrix, header, rate-limit, upload and redaction tests, e2e MFA sign-in
FIPS + docsFIPS_MODE check, PBKDF2 option; SECURITY.md with disclosure, STRIDE and the 800-171 self-mapping

  web->>api: POST /api/session (rate limited)
  api->>db: argon2 verify, lockout check
  api-->>web: mfa_required (pending session)
  User->>web: 6-digit TOTP or recovery code
  web->>api: POST /api/session/mfa

  api-->>web: session cookie (__Host- and Secure when hosted)
  Note over web: 15 min without input shows the lock screen; the password unlocks it

CMMC L2 readiness platform: how it fits together

"Rampart" (a placeholder name) is a self-hosted readiness platform for one defense contractor, run locally. You assess each of the 320 NIST 800-171A (Rev 2) objectives. It derives requirement status from them, a live SPRS score, a Conditional-status check and a POA&M checked against 32 CFR 170.21. It also manages evidence and policies and generates the SSP as a Word document.

OP 020How they connect

flowchart LR
  web -->|HTTP JSON| api
  web -->|imports for live what-if score| rules
  api -->|computes status, score, eligibility| rules
  rules -->|reads points and objective lists| catalog
  api -->|reads and writes| db
  api -->|stores and hashes files| evidencestore[evidence store]

The web UI and the API run the same rules code, so the what-if score you see and the score that's saved can never disagree.

OP 040Data

Everything is in one SQLite file written only by api. The catalog is read-only data, and each assessment records the catalog version it uses. Evidence and policy files sit in a local folder, and the database holds only their path, hash and version. Evidence flagged "contains CUI" stores a reference, never a file.

OP 060Look: C · Inspection

C's six colors and fonts, unchanged. The score is read off a vernier caliper against LSL 88 and USL 110, with a GD&T feature control frame below it. Status chips read GO / NO GO, sections carry ballooned characteristic numbers, and a red inspector's stamp reads HOLD or ACCEPT. The draft is cmmc-l2-grc-look-3.html.

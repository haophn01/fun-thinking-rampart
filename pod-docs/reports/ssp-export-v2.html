At a glance

Goal: turn Rampart's SSP export into a document a C3PAO or self-assessor recognizes: NIST's CUI SSP outline plus the 32 CFR 170.19 sections, with a pre-export check that shows what an assessor would catch.

Shipped:

  • An SSP workspace with six tabs: identification and roles, environment and diagrams, assets (five Level 2 categories), service providers with a responsibility matrix, document control, and lint and export.
  • Planned implementation and N/A rationale fields on each requirement, and a dashboard item "SSP review overdue".
  • A pre-export check (warnings only) shared by the web panel and GET /api/ssp/lint.
  • Export v2: NIST sections 1 to 4, the CMMC sections, embedded PNG/JPEG diagrams, signature lines, Appendices A and B, and an automatic record-of-changes entry on each export.
  • Migration 0005 (additive: 8 tables, 2 columns) and a templates/ folder of official reference files.

Look here first

  1. apps/api/src/ssp-data/diagrams/embeddable.ts (new in #24): decides from the stored bytes whether a diagram is PNG/JPEG. Round 1 found a GIF named .png passing. The reviewer's open someday finding is here (see What's left). A file that can't be read keeps the file name's verdict.
  2. apps/api/db/migrations/0005*: the one-way door. Additive only, tested on a 0004 database with every row kept. The human's database migrated cleanly after a backup.
  3. apps/api/ssp/render.ts and image-info.ts: the image embedding and the byte parser. Round 1 found the PR's Review guide left them out, so they got the least pointed review. Word opened a rendered file with no repair prompt (X2).
  4. apps/api/src/ssp/routes.ts: GET /api/ssp/export writes a record-of-changes row on a GET, after the render succeeds. The reviewer judged it safe because the cookie is SameSite=Strict, but it is surprising.
  5. apps/web/src/pages/ssp/SspPage.tsx and useLoad: panels stay mounted and now re-read when shown again. Round 1's two stale-data bugs lived here.

How it fits together, as built

As the plan drew it, with these differences:

  • Export split in two. The plan had one "ssp export v2" part. As built, buildSspModel (files under ssp/model/) makes the outline and ssp/render.ts with image-info.ts writes the .docx, so a later OSCAL export can reuse the outline.
  • Embeddable by bytes (ssp-data/diagrams/embeddable.ts) is new, added after round 1. The plan had the file type decide.
  • Panels re-read when their tab is shown again (useLoad): not in the plan.
  • The lint is lintSspFrom in packages/rules/src/ssp-lint, called by the api and imported by the web panel, as planned.
